# zh-Hant 引导：OpenCC `s2twp` 转换报告

本文件由 `tools/bootstrap/convert-s2twp.py` 的一次性引导生成，**不是**流水线的一部分。

## 1. 用的是哪个 OpenCC 配置，为什么

- 系统库：`libopencc1.1`（OpenCC 1.1.9，`/usr/share/opencc/`），通过 Python `ctypes` 直接调
  `opencc_open` / `opencc_convert_utf8`，没有安装 CLI，也没有往仓库加依赖。
- 配置：**`s2twp.json`**（台湾正体 + 台湾词汇表），不是 `s2t`、也不是 `s2tw`：
  - `s2t` 只换字形（`软`→`軟`），会留下「软件」这种大陆写法；
  - `s2tw` 加上台湾字形标准（`裡`/`著`/`為`），但仍不换词（`软件`→`軟件`）；
  - **`s2twp`** 再叠加 `TWPhrases`，才得到台湾实际用法（`软件`→`軟體`、
    `网络`→`網路`、`信息`→`資訊`、`打印机`→`印表機`）。繁体站的目标读者在台湾，
    所以选 `s2twp`。
- 只跑**一遍**（不做多轮 fixpoint）：OpenCC 的分词式短语替换会在长句里漏掉少数词
  （例如 `接口` 在某些上下文里没换），这类残留在报告第 5 节列出，交给
  `config/zh-hant-terms.yml` 和人工审阅，不在这里追求词表完美。

## 2. 转换了什么

- 覆盖层：`i18n/zh-Hans/**` → `i18n/zh-Hant/**`，**4704 个文件**
  （4695 个 `.md` + 9 个 `code.json`/`options.json` 等 UI 文案）。
- 术语表：`config/glossary/zh-Hans.yml` → `config/glossary/zh-Hant.yml`。
- 页面补丁：`config/translation-patches/zh-Hans/**` → `config/translation-patches/zh-Hant/**`（5 个文件）。
- `work/translate/keep-english.json` 原样复制（键是英文，与语种无关）。
- 简体覆盖层 `i18n/zh-Hans` **不保留**在本仓库：本仓只发布繁体一个语种。

## 3. 结构保护

只转中文正文，下列内容逐字节保留（已用独立脚本对 4,704 个文件逐项比对，
0 处差异）：
代码围栏（含围栏内的命令行注释）、行内代码、链接/图片地址、裸 URL、HTML/JSX
标签名与属性名、HTML 注释、MDX `{...}` 表达式与 `{#anchor}`、front matter 的
标识符键（`id`/`slug`/`sidebar_key`/`tags`/`source`/`captured_at`/…）。
链接标题（`](url "标题")`）与 `<ArgTable c1="参数">` 这类**可见**属性值属于正文，
会转换。

具体到词对：

- **已收进 `config/zh-hant-terms.yml` 的**：`資料包`→`封包`、`客戶端`→`用戶端`、
  `協議`→`協定`、`交換機`→`交換器`、`選項卡`→`標籤頁`、`除錯`→`偵錯`、
  `分割槽`→`分割區`、`網絡卡`→`網路卡`、`二維碼`→`二維條碼`、`快捷鍵`→`快速鍵`、
  `托盤`→`系統匣`、`重置`→`重設`、`程序`→`程式`、`接口`→`介面`、`端口`→`埠`、
  `搜索`→`搜尋`、`性能`→`效能`、`兼容`→`相容`（后几条在引导结果里时有时无，
  OpenCC 的分词式短语替换命中不稳定）。
- **仍待人工定稿**：
  - `區域網`/`廣域網`：OpenCC 给的是半成品（`區域網`），台湾写 `區域網路`/
    `廣域網路`；但目标词包含源词，字面替换不幂等，所以**没有**放进词表，
    只在本报告记录（需要带负向先行断言或按页替换）。
  - `訪問` vs `存取`：台湾偏 `存取`；但 `訪問` 在「访问网站」语境也对，逐句看。
  - `恢復` vs `還原`：备份/出厂设置语境台湾多用 `還原`。
  - `連接` vs `連線`：连线语境台湾用 `連線`，本语料大量出现，改动面大，先不动。
  - `許可證` vs `授權`：许可证语境台湾常用 `授權`。
  - `日誌` vs `記錄`：日志语境台湾两者混用。
  - 代码围栏内的中文注释（763 行 / 113 个文件）**保持简体**：本次按「代码块原样
    保留」处理；如需转换，走 `translate:comments` 或人工。
- UI 文案（`src/**` 里的 `COPY` 常量：首页、页脚、搜索框、版权框、宽表格）目前
  仍按 `zh-Hans` 分支硬编码，繁体站回落到英文；这些不在覆盖层里，需要单独迁移到
  `i18n/zh-Hant/docusaurus-theme-classic` 或改成按语种取文案（本次未做）。

### pending 58 的原因（未用模型补译）

`docs=8, docs-7.25=8, docs-7.24=13, hardware=29`。这些块读起来是英文、且与英文源
一致，在简体仓里由**本地的**（未入库的）`work/translate/translation-memory.json`
标记为「有意保留英文」；繁体仓没有这份 26 MB 记忆（它只存在于本地检出，CI 也不带），
所以它们重新进入待译队列。抽样类型：

- 图片 `alt` 文本（`![Network diagram: …](/img/…)`、WinBox 对话框描述）——本来就是给
  英文截图写的说明；
- 技术规格表/合规声明（`<table>` 里的 EN/DE/FR 标题、保加利亚语合规段落）；
- `knot-*` 页面里的 RouterOS 脚本注释块。

处理建议（**本次未做，零模型成本**）：把这些块加进 `work/translate/keep-english.json`
这份 ledger（设计上就是干这个的），或者接受它们作为「英文说明保留」。
