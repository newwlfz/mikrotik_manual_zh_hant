TR069-client 實現了用於遠端裝置管理的 CPE WAN Management Protocol（CWMP），該協定由 Broadband Forum（BBF）標準化。CWMP 透過 IP 網路使用 HTTP(S) 與自動配置伺服器（ACS）通訊，ACS 可以監控、配置遠端裝置的屬性並更新其韌體。它通常由 ISP 用於管理 CPE，但也可用於網路基礎設施裝置管理。

## 配置 {#configuration}

TR069-client 透過 [`/tr069-client`](../cli-reference/tr069-client/index.md) 選單進行配置。

用戶端配置包括可寫設定，例如 **enabled**、**acs-url**、**username**、**password**、**periodic-inform-enabled**、**periodic-inform-interval** 和 **client-certificate**。只讀設定（**status**、**last-session-error**、**retry-count**）用於監控用戶端狀態。[`/tr069-client/reset-tr069-config`](../cli-reference/tr069-client/reset-tr069-config.md) 命令會完全重設並清除 tr069-client 配置和狀態（不影響其他 RouterOS 配置）。當 CWMP 進入無響應或掛起狀態，並且需要在不重新安裝 RouterOS 的情況下恢復時，請使用此命令。

有關可用引數的完整列表，請參閱 [CLI 參考](../cli-reference/tr069-client/index.md)。

## CWMP 會話 {#cwmp-session}

CWMP 用戶端通常在不同事件（首次啟動、重啟、週期間隔、遠端請求、值變更等）下與 ACS 開始通訊（會話）。在每個會話中，CPE 和 ACS 可以呼叫 RPC，讓對方“執行”。CPE 始終以 Inform RPC 開始，該 RPC 包含連線原因、裝置資訊以及一些取決於配置的引數值。當 CPE 沒有更多內容要傳送時，ACS 執行其 RPC（這些大多數時候是引數管理 RPC）。

## 引數與資料模型 {#parameters-and-data-models}

引數是簡單的名稱+值對，每個廠商可以決定其裝置支援哪些引數。所有受支援引數的組合稱為資料模型（DM）。BBF 定義了三個根資料模型（TR-098、TR-181:1、TR-181:2），廠商應以其為基礎來構建其支援的引數。**RouterOS 資料模型基於 "TR-181 Issue 2 Amendment 11"**。

RouterOS TR069 用戶端支援的[引數參考](pathname:///assets/tr069_parameters.html)

## 下載 RPC {#download-rpc}

### RouterOS 更新（1 Firmware Upgrade Image） {#routeros-update-1-firmware-upgrade-image}

CWMP 標準規定，可以使用 Download RPC 並透過 FileType="1 Firmware Upgrade Image" 以及一個可下載檔案的單個 URL（支援 HTTP 和 HTTPS）來更新 CPE 的韌體。該標準還指出，下載的檔案可以是任意型別，並且可以應用廠商特定的流程來完成韌體更新。由於 MikroTik 的更新基於軟體包（同時也是為了額外的靈活性），因此使用 XML 檔案來描述韌體升級/降級。目前，XML 配置支援提供多個檔案 URL，這些檔案將被下載，並像透過韌體/軟體包檔案上傳進行常規 RouterOS 更新一樣應用。

以下是 RouterOS bundle 軟體包和 tr069-client 軟體包更新的示例（請確保也更新 tr069-client 軟體包）。將 XML 檔案放在 CPE 可訪問的 HTTP 伺服器上以供下載。可下載的 RouterOS 軟體包檔案必須以相同方式可訪問（它們可以位於任意 HTTP 伺服器上）。使用 ACS 執行 Download RPC，將 URL 指向該 XML 檔案（例如 "https://example.com/path/upgrade.xml"），其內容如下：

```
<upgrade version="1" type="links">
   <config/>
   <links>
       <link>
          <url>https://example.com/routeros-mipsbe-X.Y.Z.npk</url>
       </link>
       <link>
          <url>https://example.com/tr069-client-X.Y.Z-mipsbe.npk</url>
       </link>
   </links>
</upgrade>

```

CPE 會下載該 XML，解析並驗證其內容，從提供的 URL 下載檔案，並嘗試升級。結果透過 TransferComplete RPC 報告。

:::info
始終以增量方式進行韌體更新——首先，更新一臺經過本地測試的裝置，並確保在新版本下恢復 CWMP 通訊，且所需的 RouterOS 功能正常工作。然後，透過逐步更新 CPE 組來重複這些步驟。不應一次性更新所有遠端裝置。

在生產環境中使用 HTTPS 進行韌體管理。
:::

### 配置更改（3 Vendor Configuration File） {#configuration-change-3-vendor-configuration-file}

同一個 Download RPC 可用於執行完整配置覆蓋（按標準意圖）或配置修改（當 URL 的檔名副檔名為 ".alter" 時）。

### 修改配置 {#alter-configuration}

RouterOS 有許多配置屬性，並非所有內容都能對映到 CWMP 引數。這就是 RouterOS 提供執行其強大指令碼語言的能力來配置任意屬性的原因。配置更改（即常規指令碼執行）可以使用 Download RPC 執行，其中 FileType="3 Vendor Configuration File"，且可下載檔案的副檔名為 ".alter"。此功能可用於配置透過 CWMP 引數無法提供的任何 RouterOS 屬性。

### 覆蓋所有配置 {#overwrite-all-configurations}

可以使用 Download RPC FileType="3 Vendor Configuration File" 並搭配任意 URL 檔名（".alter" 副檔名除外）來執行完整的 ROS 配置覆蓋。

:::warning
提供的配置檔案（指令碼）必須足夠健壯，以便在重啟後立即正確應用配置。當使用透過 Upload RPC 上傳的配置檔案時，這一點尤為重要，因為它只包含匯出的值。必須手動新增的一些內容：

- [啟動延遲](../getting-started/configuration-management/index.md#startup-delay)：介面出現所需的時間。
- Hidden passwords for users.
- [證書](../authentication-authorization-accounting/certificates.md).
:::

### RouterOS 預設配置更改（X MIKROTIK Factory Configuration File） {#routeros-default-configuration-change-x-mikrotik-factory-configuration-file}

此廠商特定的 FileType 允許更改 RouterOS 預設配置指令碼；當執行 [`/system/reset-configuration`](../cli-reference/system/reset-configuration.md) 命令時（或透過其他方式重設路由器配置時），該指令碼會被執行。

:::warning
如果更改了預設配置指令碼，則 [`/system/default-configuration/print`](../cli-reference/system/default-configuration/index.md) 不會顯示它，而使用 Netinstall 工具修改該指令碼時則會顯示。該命令將始終顯示由 MikroTik 設定的預設指令碼。

請謹慎使用此功能，因為上傳的指令碼失敗可能會導致裝置無法執行，或使 ACS 無法訪問裝置。
:::

## FactoryReset RPC {#factoryreset-rpc}

這是一個 CWMP 標準 RPC，用於執行 RouterOS 配置出廠重設。重設過程的執行方式與執行以下命令相同：

```
/system/reset-configuration skip-backup=yes

```

請注意，出廠預設配置可能因裝置而異（參見[預設配置](../getting-started/configuration-management/default-configurations.md)），並且執行此命令會移除所有配置並執行內部儲存的 default-configuration 指令碼。

## 上傳 RPC {#upload-rpc}

### 上傳當前配置（1 Vendor Configuration File） {#upload-current-configuration-1-vendor-configuration-file}

結果是一個上傳到 ACS 的檔案，與 RouterOS 中 `/export` 命令的輸出相同。

### 上傳日誌檔案（2 Vendor Log File） {#upload-log-file-2-vendor-log-file}

結果是一個上傳到 ACS 的檔案，類似於 RouterOS 中 [`/log/print`](../cli-reference/log.md) 命令的輸出。

### 上傳預設配置（X MIKROTIK Factory Configuration File） {#upload-default-configuration-x-mikrotik-factory-configuration-file}

結果是一個上傳到 ACS 的檔案，其內容為當前預設配置指令碼；如果執行 `/system/reset-configuration` 命令，該指令碼將被執行。它可能與 `/system/default-configuration/print` 返回的內容不同。

## 安全性 {#security}

- 僅在安全或專用網路中測試初始設定時使用 HTTP，因為中間人攻擊者可能讀取或更改配置引數。**在生產環境中，必須使用 HTTPS。**
- CWMP 的傳入連線驗證在設計上是安全的，因為 CPE 不會與先前配置的 ACS 以外的任何裝置通訊。Connection Request 僅通知 CPE 與先前配置的 ACS 啟動新連線和會話。

## 讓路由器準備好用於 TR069 {#get-the-router-ready-for-use-with-tr069}

本最佳實踐指南展示了一個 RouterOS 初始設定示例，適用於需要安全、預配置且帶自定義配置的恢復出廠設定時，尤其是在使用 TR-069 時。當裝置被（使用者或提供商在不知情的情況下）錯誤配置到不可逆狀態時，這可能很有用。恢復出廠設定配置可以使用 TR069 FactoryReset RPC、透過 RouterOS `/system/reset-configuration`，或使用路由器上的復位按鈕來應用。

### 在 Netinstall 上覆蓋出廠預設配置 {#overriding-factory-default-configurations-on-netinstall}

執行 Netinstall 時，可以調整預設配置指令碼以滿足特定需求，並透過覆蓋 MikroTik 的預設指令碼來安裝。希望將 FactoryReset 作為後備手段、以便在出現無法解決的錯誤配置後讓裝置重新可達的提供商應這樣做。在 TR-069 場景下，預設配置指令碼至少應匯入證書、設定 IP 層連通性、啟用並配置 tr069-client，以及配置防火牆。之後，其他配置可以由 ACS 執行。

:::warning
恢復出廠設定時，所有證書都會被移除，因此如果重設後需要這些證書，預設配置指令碼必須匯入它們。
:::
