## 概述 {#summary}

SwOS Lite 是一款專為管理 MikroTik CSS610 系列交換器產品而設計的作業系統。CSS610 系列交換器僅支援 SwOS Lite 作業系統。

與 CSS3xx 系列交換器相比，主要區別在於：

- 不支援 Independent VLAN Learning
- 不支援 VLAN 模式 "enabled"
- 不支援 ACL 速率限制
- 支援埠出方向速率限制

---

## 連線到交換器 {#connecting-to-the-switch}

開啟 Web 瀏覽器，輸入交換器的 IP 地址（預設為 192.168.88.1），隨後會出現登入螢幕。交換器也可以執行 DHCP 用戶端，請檢查 DHCP 伺服器是否已分配其他 IP 地址。

![Swos login css610](/img/388461ec86ffddb8.webp)

SwOS 預設 IP 地址：**192.168.88.1**，使用者名稱：**admin**，並且沒有密碼。

[鄰居發現](../../system-information-and-utilities/neighbor-discovery.md) 可用於發現 Mikrotik 交換器的 IP 地址。不支援 LLDP。

## 介面概覽 {#interface-overview}

SwOS 介面選單根據裝置型號由多個標籤頁組成。SwOS 可能包含的所有選單為：Link、PoE、SFP、Port Isolation、LAG、Forwarding、RSTP、Stats、Errors、Hist、VLAN、VLANs、Hosts、IGMP、SNMP、ACL、System、Health 與 Upgrade。

SwOS 配置工具中按鈕的說明：

- **Append** - 在列表末尾新增新條目
- **Apply All** - 應用當前的配置更改
- **Cut** - 從列表中刪除條目
- **Clear** - 重設條目的屬性
- **Discard Changes** - 丟棄未儲存的配置
- **Insert** - 在列表中新增新條目（放置於當前條目之前）
- **Sort** - 按 VLAN ID 對 VLAN 表排序；按 MAC 地址對主機表排序
- **Change Password** - 更改交換器密碼
- **Logout** - 從當前交換器登出
- **Reboot** - 重啟交換器
- **Reset Configuration** - 將配置恢復為出廠預設值
- **Choose File** - 瀏覽以選擇升級或備份檔案
- **Upgrade** - 使用所選檔案升級交換器韌體
- **Download & Upgrade** - 自動嘗試下載並升級韌體，執行 Web 瀏覽器的 PC 應能訪問 Internet
- **Restore Backup** - 使用所選備份檔案恢復交換器
- **Save Backup** - 從交換器生成並下載備份檔案

> **注意：** 每個 RouterBoard 交換器系列裝置都有各自的韌體，不能安裝在其他系列型號上！
>
> - CSS610-1Gi-7R-2S+ 支援 SwOS Lite v2.12 及更新版本。
> - CSS610-8G-2S+ 支援 SwOS Lite v2.12 及更新版本。
> - CSS610-8P-2S+IN 支援 SwOS Lite v2.15 及更新版本。

## 埠隔離 {#port-isolation}

Port Isolation 表允許或限制特定埠之間的流量轉發。預設情況下，所有可用的交換晶片埠都能與任意其他埠通訊 —— 不使用隔離。勾選複選框後，即允許流量從該埠轉發到被勾選的埠。以下是一些埠隔離示例。

![SwOS Isolated Groups](/img/284614f24611b0f4.webp)

在某些場景下，你可能需要將一組裝置與其他組隔離。在此示例中，**Port1-Port5** 上的裝置無法與 **Port6-Port10** 上的裝置通訊，反之亦然。

![SwOS Private VLAN](/img/606fbb63c2620b62.webp)

在某些場景下，你可能需要將所有流量轉發到上行埠，同時讓所有其他埠彼此隔離。這種配置稱為 **Private VLAN** 配置。交換器會將所有乙太網幀僅轉發到上行埠 **Port1**，而上行埠可以訪問所有其他埠。

![SwO isolation example3](/img/de28135343d9795b.webp)

單獨隔離的 **Port1**（例如用於管理目的）—— 它無法向任何其他埠傳送流量，也無法從任何其他埠接收流量。

> **注意：** 可以透過勾選其中一個複選框，然後水平拖動（單擊並拖動）來勾選/取消勾選多個複選框。

> **注意：** (R)STP 僅在 Private VLAN 配置中才能正常工作。在包含多個隔離交換器組的配置中，(R)STP 可能無法正確接收 BPDU，從而無法檢測網路環路。

## LAG {#lag}

支援相容 IEEE 802.3ad (LACP) 的鏈路聚合，也支援靜態鏈路聚合，以僅基於二層雜湊實現故障切換和負載均衡。最多支援 16 個鏈路聚合組，每組最多 8 個埠。每個單獨的埠都可以配置為 Passive LACP、Active LACP 或 Static LAG 埠。

| 屬性 | 描述 |
| --- | --- |
| **模式** *（預設值：passive）* | 指定埠上的 LACP 封包交換模式或 Static LAG 模式：`Passive` - 將埠置於監聽狀態，僅當對端埠使用主動 LACP 模式時才使用 LACP`Active` - 優先啟動 LACP，無論對端埠模式如何`Static` - 將埠設定為 Static LAG 模式；需要為所有要加入同一靜態 LAG 的埠設定相同的 **Group** 設定 |
| **組** | 指定靜態 LAG 組 |
| **Trunk** *（只讀）* | 表示埠所屬的組編號 |
| **Partner** *（只讀）* | 表示對端 MAC 地址；僅在埠加入 LACP 時可用 |

## 轉發 {#forwarding}

Forwarding 標籤頁提供交換器埠之間的高階轉發選項、埠鎖定、埠映象、頻寬限制和廣播風暴控制功能。

![Swos forw css610](/img/41fc3bd40fd23388.webp)

| 屬性 | 描述 |
| --- | --- |
| **埠鎖定** | `Port Lock` - 啟用或停用該埠上的 MAC 地址學習。啟用該選項後，將限制 MAC 地址學習，此時應配置靜態 MAC 地址。任何源 MAC 地址未知的接收幀都將被丟棄`Lock On First` - 允許從第一個接收幀中學習源 MAC 地址；該屬性應與 `Port Lock` 一起使用。每當介面狀態發生變化時，首個 MAC 地址的學習都會被重設 |
| **埠映象** | `Mirror Ingress` - 進入該埠的流量是否必須複製並轉發到映象目標埠`Mirror Egress` - 離開該埠的流量是否必須複製並轉發到映象目標埠`Mirror To` - 映象目標埠 |
| **廣播風暴控制** | `Storm Rate` - 限制介面傳送的廣播封包數量。速率以位元每秒（bps）為單位`Include Unknown Unicast` - 將主機表中無對應條目的單播封包納入 `Storm Rate` 限制 |
| **組播泛洪控制** | `Flood Unknown Multicast` - 更改交換器埠上的組播泛洪選項；僅控制出方向流量。啟用時，網橋允許將組播封包泛洪到指定交換器埠；停用時，則限制組播流量泛洪。該設定影響所有組播流量，包括非 IP、IPv4、IPv6 以及鏈路本地組播範圍（例如 224.0.0.0/24 和 ff02::1） |
| **Bandwidth Limit** | `Ingress Rate` - 限制進入此埠的流量（bps）`Egress Rate` - 限制離開此埠的流量（bps） |

> **注意：** 可以按埠限制入方向/出方向流量。入方向流量使用 policer，出方向流量使用 shaper。入方向 policer 透過丟包來控制接收的流量 —— 所有超過所定義限制的流量都會被丟棄。這可能影響終端主機上的 TCP 擁塞控制機制，實際達到的頻寬可能小於所定義的值。出方向 shaper 會嘗試將超過限制的封包排隊，而不是丟棄它們。最終，當輸出佇列滿時它也會丟棄封包；不過，它應能更好地利用所定義的吞吐量。

## RSTP {#rstp}

RSTP 選單中提供每埠和全域性 RSTP 配置與監控。

![Swos rstp css326](/img/6e7df850ef26634b.webp)

| 屬性 | 描述 |
| --- | --- |
| **網橋優先順序（十六進位制）** | 用於根網橋選擇的 RSTP 網橋優先順序 |
| **埠開銷模式** | 有兩種方法可根據鏈路速率自動檢測 RSTP 埠開銷。`short`: 40G - 1; 10G - 2; 1G - 4; 100M - 10; 10M - 100`long`: 40G - 500; 10G - 2000; 1G - 20000; 100M - 200000; 10M - 2000000 |
| **轉發保留組播** | 是否轉發 **01:80:C2:00:00:0x** 範圍內的 IEEE 保留組播 MAC 地址。符合 R/M/STP 標準的交換器應避免轉發這些封包。如果啟用此設定，SwOS 將轉發保留組播 MAC 封包並停用 RSTP：- 交換器將不處理傳入的 BPDU（橋接協定資料單元）- 它也不會發送自己的 BPDU- 網橋優先順序和按埠的 RSTP 配置設定將不再有任何效果。啟用保留 MAC 地址的轉發可能影響依賴這些地址的某些協定。建議僅在絕對必要時才啟用轉發，例如在透明橋接配置中（例如延長長距離鏈路、將網橋用作介質轉換器或進行網路分析）。值得注意的 MAC 地址和協定示例（RouterOS 使用的）：`01:80:C2:00:00:00` - 生成樹協定（STP）`01:80:C2:00:00:01` - 乙太網流控`01:80:C2:00:00:02` - 鏈路聚合控制協定（LACP）`01:80:C2:00:00:03` - Dot1x 用戶端和伺服器`01:80:C2:00:00:08` - 生成樹協定（用於 802.1ad 網橋，使用 `ether-type=0x88a8`）`01:80:C2:00:00:0D` - 多 VLAN 註冊協定（用於 802.1ad 網橋，使用 `ether-type=0x88a8`）`01:80:C2:00:00:0E` - 鏈路層發現協定、多機箱鏈路聚合組和精確時間協定流控 MAC 地址 `01:80:C2:00:00:01` 是一個例外 —— 它不會被 SwOS 轉發。 |
| **根網橋** | 網路中所選根網橋的優先順序和 MAC 地址（只讀） |
| **RSTP** | 啟用或停用該埠上的 STP/RSTP 功能 |
| **模式** | 顯示特定埠上的 STP/RSTP 功能模式（只讀）：`RSTP``STP` |
| **角色** | 顯示特定埠角色（只讀）：`root` - 朝向根網橋並將用於向根網橋轉發流量或從根網橋轉發流量的埠`alternate` - 朝向根網橋但不轉發流量的埠（根埠的備份）`backup` - 背向根網橋但不轉發流量的埠（非根埠的備份）`designated` - 背向根網橋並會轉發流量的埠`disabled` - 嚴格來說不屬於 STP 的埠（RSTP 功能已停用） |

| **狀態** | 顯示每個埠的狀態（只讀）：`forwarding` - 埠參與流量轉發並學習 MAC 地址，正在接收 BPDU`discarding` - 埠不參與流量轉發且不學習 MAC 地址，正在接收 BPDU`learning` - 埠不參與流量轉發但正在學習 MAC 地址 |

## VLAN 與 VLANs {#vlan-and-vlans}

交換器埠的 VLAN 配置。

![Swos vlan css610](/img/3441762ea56c20d5.webp)

| 屬性 | 描述 |
| --- | --- |
| **VLAN 模式**（*disabled \| optional \| strict*；預設值：**optional**） | VLAN 過濾模式；這些選項與出方向埠相關（strict 模式除外）。`disabled` - 不使用 VLAN 表。交換器在出方向埠上丟棄帶 VLAN 標籤的封包。如果封包帶有 VLAN 標籤且其 VLAN ID 與出方向埠上的 `Default VLAN ID` 匹配，那麼在 `VLAN Receive=any` 的情況下，交換器將移除 VLAN 標籤並轉發該封包。`optional` - 停用 VLAN 過濾。對於 VLAN 標籤 ID 不在 VLAN 表中的封包，與不帶 VLAN 標籤的封包同等處理。`strict` - 啟用 VLAN 過濾，並附加入方向過濾，即檢查入方向埠是否為所接收 VLAN ID 在 VLAN 表中的成員。入方向埠上接收到的 VLAN ID 與 VLAN 表不匹配的封包將被丟棄。必須為接入埠指定 Default VLAN ID，因為它將用於為特定埠的入方向流量打標籤、為出方向流量去標籤。 |
| **VLAN Receive** (*any \| only tagged \| only untagged*；預設：**optional**) | 基於 VLAN 標籤存在情況對接收流量進行過濾。`any` - 允許某個埠上的帶標籤和無標籤封包`only tagged` - 僅允許帶有 VLAN 標籤的封包。"Default VLAN ID" 將不起作用，因為它僅適用於無標籤流量`only untagged` - 僅允許不帶 VLAN 標籤的封包 |
| **預設 VLAN ID**（*integer: 1..4095*；預設值：**1**） | 交換器將接收到的未打標籤封包放入 "Default VLAN ID" 所指定的 VLAN。僅對不帶標籤的流量生效，且當 **VLAN Receive** 設定為 "any" 或 "only untagged" 時生效。不適用於帶標籤的流量。此引數通常用於為接入埠分配特定的 VLAN。如果封包的 VLAN ID 與 Default VLAN ID 匹配，它也用於為出方向流量去除標籤。 |
| **Force VLAN ID** (*yes \| no*；預設：**no**) | 將所有入口流量（帶標籤和無標籤）分配為 `Default VLAN ID` 值。在所有 VLAN 模式下均有效。如果埠接收帶標籤流量，且 `Default VLAN ID` 設定為 1，則使用此引數後，出口流量將不帶標籤。 |

交換器埠的 VLAN 成員關係配置。

![Swos vlans css610](/img/bdb180a9a3afc27b.webp)

| 屬性 | 描述 |
| --- | --- |
| **VLAN ID**（*integer: 1..4095*；預設值：**0**） | 要為埠分配的 VLAN ID |
| **IGMP Snooping**（*yes \| no*；預設值：**no**） | 在指定 VLAN 上啟用或停用 IGMP Snooping。啟用後，交換器將監聽來自該 VLAN 的 IGMP Join 和 Leave 請求，並僅向從該 VLAN 傳送過 IGMP 成員關係請求的埠轉發流量。停用時，交換器會向所有 VLAN 成員埠泛洪組播流量。 |
| **成員**（*ports*；預設值：**none**） | 允許在指定 VLAN 上轉發流量的埠組 |

## 主機 {#hosts}

該表表示動態學習到的 MAC 地址到埠的對映條目。它可以包含兩種條目：動態和靜態。動態條目會自動新增 —— 這也稱為學習過程：當交換器從某個埠接收到封包時，它會將該封包的源 MAC 地址以及接收到該封包的埠新增到主機表中，這樣當帶有特定目標 MAC 地址的封包到達時，它就知道應該將封包轉發到哪個埠。如果目標 MAC 地址不在主機表中，則它會將封包轉發到該組中的所有埠。動態條目大約需要 5 分鐘超時。

如果已存在具有相同 MAC 地址的動態條目，靜態條目將取代動態條目。新增靜態條目還可獲得更多功能。

![Swos shost css610](/img/d22df8b89cf64db5.webp)

**靜態主機屬性**

| 屬性 | 描述 |
| --- | --- |
| **埠** | 封包應轉發到的埠 |
| **MAC** | MAC 地址 |

**動態主機屬性（只讀）**

| 屬性 | 描述 |
| --- | --- |
| **埠** | 封包應轉發到的埠 |
| **MAC** | 學習到的 MAC 地址 |

## SNMP {#snmp}

SwOS 支援 SNMP v1 和 v2c（對 GetRequest、GetNextRequest 和 GetBulkRequest 的響應），並使用 IF-MIB、SNMPv2-MIB、BRIDGE-MIB 和 MIKROTIK-MIB（僅用於 health、PoE-out 和 SFP 診斷）。不支援 SNMP trap 和寫入 SwOS 配置。

## ACL 與 ACL Stats 標籤頁 {#acl-and-acl-stats-tabs}

訪問控制列表（ACL）規則表是一個非常強大的工具，可基於 L2、L3 和 L4 協定頭欄位條件實現線速的封包過濾、轉發和 VLAN 打標籤。每條規則包含條件部分和動作部分。

![CSS610 ACL table](/img/38f5c04e1dfbc157.webp)

**條件部分引數**

| 屬性 | 描述 |
| --- | --- |
| **From** | 封包進入的埠 |
| **MAC Src** | 源 MAC 地址和掩碼 |
| **MAC Dst** | 目標 MAC 地址和掩碼 |
| **Ethertype** | 封裝在乙太網幀有效載荷中的協定 |
| **VLAN** | VLAN 頭是否存在：`any` / `present` / `not present` |
| **VLAN ID** | VLAN 標籤 ID |
| **Priority** | VLAN 標籤中的優先順序 |
| **IP Src**（IP/netmask:port） | 源 IPv4 地址、子網掩碼和 L4 埠號 |
| **IP Dst**（IP/netmask:port） | 目標 IPv4 地址、子網掩碼和 L4 埠號 |
| **Protocol** *（integer）* | IP 協定 |
| **DSCP** | IP DSCP 欄位 |

**動作部分引數**

| 屬性 | 描述 |
| --- | --- |
| **Account as** | 選擇用於統計匹配封包的計數器 |
| **Redirect To** | 強制設定新封包的目標埠 |
| **Mirror** | 克隆封包並將其傳送到映象目標埠 |
| **Drop** | 丟棄封包 |
| **Set VLAN ID** | 如果存在 VLAN 標籤，則更改 VLAN 標籤 ID |
| **Priority** | 如果存在 VLAN 標籤，則更改 VLAN 標籤優先順序位 |
| **DSCP** | 更改 IP DSCP 欄位 |

每條 ACL 規則都可以分配到特定的計數器，匹配的封包將在其中被統計。

## 重設與重新安裝 {#reset-and-reinstall}

CSS610 內建備份 SwOS 韌體，可在標準韌體損壞或升級失敗時載入：

- 在裝置啟動時按住 Reset 按鈕幾秒鐘將重設配置並載入備份韌體。
- 載入備份韌體後，可以使用 Web 瀏覽器連線到 192.168.88.1（或從 DHCP 伺服器租用的地址）並安裝新的 SwOS 韌體。
