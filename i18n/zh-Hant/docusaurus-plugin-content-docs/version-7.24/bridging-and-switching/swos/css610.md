## 摘要 {#summary}

SwOS Lite 是專為管理 MikroTik CSS610 系列交換器產品而設計的作業系統。CSS610 系列交換器僅支援 SwOS Lite 作業系統。

與 CSS3xx 系列交換器相比，主要差異如下：

- 不支援 Independent VLAN Learning
- 不支援 VLAN 模式「enabled」
- 不支援 ACL 速率限制
- 支援埠出口速率限制

---

## 連線至交換器 {#connecting-to-the-switch}

開啟網頁瀏覽器，並輸入交換器的 IP 位址（預設為 192.168.88.1），畫面會顯示登入畫面。交換器也可以執行 DHCP 用戶端，請查看 DHCP 伺服器是否指派了不同的 IP 位址。

![Swos login css610](/img/388461ec86ffddb8.webp)

SwOS 預設 IP 位址：**192.168.88.1**，使用者名稱：**admin**，且沒有密碼。

[MikroTik Neighbor Discovery](/docs/system-information-and-utilities/neighbor-discovery) 可用於探索 Mikrotik 交換器的 IP 位址。不支援 LLDP。

## 介面概觀 {#interface-overview}

SwOS 介面選單由多個標籤頁組成，實際項目取決於設備型號。以下是所有可能的 SwOS 選單：Link、PoE、SFP、Port Isolation、LAG、Forwarding、RSTP、Stats、Errors、Hist、VLAN、VLANs、Hosts、IGMP、SNMP、ACL、System、Health 與 Upgrade。

SwOS 設定工具中按鈕的說明：

- **Append** - 在清單結尾新增項目
- **Apply All** - 套用目前的設定變更
- **Cut** - 從清單中移除項目
- **Clear** - 重設項目的屬性
- **Discard Changes** - 移除未儲存的設定
- **Insert** - 在清單中新增項目（放在目前項目之前）
- **Sort** - 依 VLAN-ID 排序 VLAN 表；依 MAC 位址排序主機表
- **Change Password** - 變更交換器的密碼
- **Logout** - 登出目前交換器
- **Reboot** - 重新啟動交換器
- **Reset Configuration** - 將設定重設回原廠預設值
- **Choose File** - 瀏覽升級或備份檔案
- **Upgrade** - 使用所選檔案升級交換器韌體
- **Download & Upgrade** - 自動嘗試下載並升級韌體，執行網頁瀏覽器的電腦必須能存取網際網路
- **Restore Backup** - 使用所選備份檔案還原交換器
- **Save Backup** - 從交換器產生並下載備份檔案

> **注意：** 每個 RouterBoard 交換器系列設備都有專屬韌體，無法安裝在其他系列型號上！
>
> - CSS610-1Gi-7R-2S+ 支援 SwOS Lite v2.12 及以上版本。
> - CSS610-8G-2S+ 支援 SwOS Lite v2.12 及以上版本。
> - CSS610-8P-2S+IN 支援 SwOS Lite v2.15 及以上版本。

## 埠隔離 {#port-isolation}

Port Isolation 表格可允許或限制特定埠之間的流量轉送。預設情況下，所有可用的交換器晶片埠都可以與任何其他埠通訊，未使用任何隔離。當勾選核取方塊時，您允許流量從此埠轉送至已勾選的埠。以下為一些連接埠隔離範例。

![SwOS Isolated Groups](/img/284614f24611b0f4.webp)

在某些情境下，你可能需要將一組設備與其他群組隔離。在此範例中，**Port1-Port5** 上的設備無法與 **Port6-Port10** 的設備通訊，反之亦然。

![SwOS Private VLAN](/img/606fbb63c2620b62.webp)

在某些情境下，你可能需要將所有流量轉送至 uplink 埠，同時讓其他所有埠彼此隔離。這種設定稱為 **Private VLAN** 組態。交換器只會將所有 Ethernet 訊框轉送至 uplink **Port1**，而 uplink 可以連線至其他所有埠。

![SwO isolation example3](/img/de28135343d9795b.webp)

個別隔離的 **Port1**（例如用於管理目的）無法從任何其他埠傳送或接收流量。

> **Note:** 勾選其中一個核取方塊後水平拖曳（Click & Drag），即可一次勾選或取消勾選多個核取方塊。

> **Note:** (R)STP 僅在 Private VLAN 設定中能正常運作。在具有多個隔離交換器群組的設定中，(R)STP 可能無法正確接收 BPDU，因此無法偵測網路迴圈。

## LAG

支援 IEEE 802.3ad (LACP) 相容的鏈路彙總，也支援靜態鏈路彙總，以確保僅根據 Layer2 雜湊進行故障切換與負載平衡。最多支援 16 個鏈路彙總群組，每個群組最多 8 個埠。每個個別埠都可以設定為 Passive LACP、Active LACP 或 Static LAG 埠。

| Property | Description |
| --- | --- |
| **Mode** *(default: passive)* | 指定埠上的 LACP 封包交換模式或 Static LAG 模式：<br/><code>Passive</code> - 讓埠進入 listening 狀態，只有當對端埠使用 active LACP 模式時才使用 LACP<br/><code>Active</code> - 偏好開始 LACP，不論對端埠模式為何<br/><code>Static</code> - 將埠設定為 Static LAG 模式；所有需要加入同一個 static LAG 的埠都必須設定相同的 <strong>Group</strong> 設定 |
| **Group** | 指定 Static LAG 群組 |
| **Trunk** *(read-only)* | 表示埠所屬的群組編號 |
| **Partner** *(read-only)* | 表示對端 MAC 位址；僅當埠包含在 LACP 中時可用 |

## Forwarding

Forwarding Tab 提供交換器埠之間的進階轉送選項、埠鎖定、埠鏡像、頻寬限制與廣播風暴控制功能。

![Swos forw css610](/img/41fc3bd40fd23388.webp)

| 屬性 | 說明 |
| --- | --- |
| **Port Lock** | <code>Port Lock</code> - 啟用或停用此埠的 MAC 位址學習。啟用此選項時，會限制 MAC 位址學習，並應設定靜態 MAC 位址。任何接收到來源 MAC 位址未知的訊框都會被丟棄<br/><code>Lock On First</code> - 允許從接收到的第一個訊框學習來源 MAC 位址；此屬性應與 <code>Port Lock</code> 一起使用。每次介面狀態變更時，第一個 MAC 位址的學習都會重設 |
| **Port Mirroring** | <code>Mirror Ingress</code> - 進入此埠的流量是否必須複製並轉送至鏡像目標埠<br/><code>Mirror Egress</code> - 離開此埠的流量是否必須複製並轉送至鏡像目標埠<br/><code>Mirror To</code> - 鏡像目標埠 |
| **Broadcast Storm Control** | <code>Storm Rate</code> - 限制介面傳輸的廣播封包數量。速率以每秒位元數（bps）為單位<br/><code>Include Unknown Unicast</code> - 在主機表中沒有項目的單播封包是否納入 <code>Storm Rate</code> 限制 |
| **Multicast Flood Control** | `Flood Unknown Multicast` - 變更交換器埠的群播氾濫選項；僅控制輸出流量。啟用時，bridge 允許將群播封包氾濫至指定的交換器埠；停用時，會限制群播流量遭到氾濫。此設定會影響所有群播流量，包括非 IP、IPv4、IPv6 及 link-local 群播範圍（例如 224.0.0.0/24 與 ff02::1） |
| **Bandwidth Limit** | <code>Ingress Rate</code> - 限制進入此埠的流量（bps）<br/><code>Egress Rate</code> - 限制離開此埠的流量（bps） |

> **注意：** 可以依據每個埠限制輸入／輸出流量。policer 用於輸入流量，shaper 用於輸出流量。輸入 policer 會以丟棄封包的方式控制接收到的流量，所有超過定義限制的内容都會被丟棄。這可能會影響終端主機上的 TCP 壅塞控制機制，實際達成的頻寬可能低於定義值。輸出 shaper 會嘗試將超過限制的封包排入佇列，而不是直接丟棄。最終，當輸出佇列已滿時，它仍會丟棄封包；不過，這應能更好地運用定義的輸送量。

## RSTP

每埠與全域 RSTP 設定及監控可在 RSTP 選單中使用。

![Swos rstp css326](/img/6e7df850ef26634b.webp)

| 屬性 | 說明 |
| --- | --- |
| **Bridge Priority (hex)** | 用於 Root Bridge 選擇的 RSTP bridge priority |
| **Port Cost Mode** | 有兩種方法可依據鏈路速度自動偵測 RSTP 埠成本。<br/><code>short</code>: 40G - 1; 10G - 2; 1G - 4; 100M - 10; 10M - 100<br/><code>long</code>: 40G - 500; 10G - 2000; 1G - 20000; 100M - 200000; 10M - 2000000 |
| **Forward Reserved Multicast** | 是否轉送位於 <strong>01:80:C2:00:00:0x</strong> 範圍內的 IEEE 保留群播 MAC 位址。符合 R/M/STP 標準的交換器應避免轉送這些封包。<br/><br/>如果啟用此設定，SwOS 會轉送保留的群播 MAC 封包並停用 RSTP：<br/>- 交換器不會處理傳入的 BPDU（Bridge Protocol Data Units）<br/>- 也不會傳送自身的 BPDU<br/>- Bridge Priority 與每埠 RSTP 設定將不再生效。<br/><br/>啟用保留 MAC 位址的轉送可能會影響依賴這些位址的特定協定。建議僅在絕對必要時啟用轉送，例如透明橋接環境（例如延伸長距離鏈路、將 bridge 作為媒體轉換器，或進行網路分析）。<br/><br/>值得注意的 MAC 位址與協定範例（由 RouterOS 使用）：<br/><code>01:80:C2:00:00:00</code> - Spanning Tree Protocol (STP)<br/><code>01:80:C2:00:00:01</code> - Ethernet Flow Control<br/><code>01:80:C2:00:00:02</code> - Link Aggregation Control Protocol (LACP)<br/><code>01:80:C2:00:00:03</code> - Dot1x client and server<br/><code>01:80:C2:00:00:08</code> - Spanning Tree Protocol（適用於 802.1ad bridge，使用 <code>ether-type=0x88a8</code>）<br/><code>01:80:C2:00:00:0D</code> - Multiple VLAN Registration Protocol（適用於 802.1ad bridge，使用 <code>ether-type=0x88a8</code>）<br/><code>01:80:C2:00:00:0E</code> - Link Layer Discovery Protocol、Multi-chassis Link Aggregation Group 與 Precision Time Protocol<br/><br/>Flow Control MAC 位址 <code>01:80:C2:00:00:01</code> 是例外，SwOS 不會轉送它。 |
| **Root Bridge** | 網路中所選 Root Bridge 的優先順序與 MAC 位址（唯讀） |
| **RSTP** | 在此埠啟用或停用 STP/RSTP 功能 |
| **Mode** | 顯示特定埠上的 STP/RSTP 功能模式（唯讀）：<br/><code>RSTP</code><br/><code>STP</code> |
| **Role** | 顯示特定埠角色（唯讀）：<br/><code>root</code> - 面向 root bridge 的埠，將用於轉送往返 root bridge 的流量<br/><code>alternate</code> - 面向 root bridge 的埠，但不會轉送流量（root port 的備援）<br/><code>backup</code> - 背向 root bridge 的埠，但不會轉送流量（非 root port 的備援）<br/><code>designated</code> - 背向 root bridge 且將會轉送流量的埠<br/><code>disabled</code> - 不嚴格屬於 STP 的埠（RSTP 功能已停用） |
| **Root Path Cost** | 顯示面向 root bridge 的埠之路徑成本（唯讀） |
| **Type** | <code>edge</code> - 不應接收任何 BPDU 的埠，應連接至終端設備（唯讀）<br/><code>point-to-point</code> - 操作於全雙工鏈路的埠，可成為 STP 的一部分並處於 forwarding 狀態（唯讀） |
| **State** | 顯示每個埠狀態（唯讀）：<br/><code>forwarding</code> - 埠參與流量轉送並正在學習 MAC 位址，且正在接收 BPDU<br/><code>discarding</code> - 埠不參與流量轉送且不學習 MAC 位址，正在接收 BPDU<br/><code>learning</code> - 埠不參與流量轉送但正在學習 MAC 位址 |

## VLAN 與 VLANs {#vlan-and-vlans}

交換器埠的 VLAN 設定。

![Swos vlan css610](/img/3441762ea56c20d5.webp)

| Property | Description |
| --- | --- |
| **VLAN Mode** (*disabled \| optional \| strict*; Default: **optional**) | VLAN  filtering 模式；這些選項與 egress 埠相關（strict 模式除外）。<br/><code>disabled</code> - 不使用 VLAN 表。交換器會捨棄 egress 埠上帶有 VLAN 標籤的封包。如果封包帶有 VLAN 標籤，且 VLAN ID 與 egress 埠上的 <code>Default VLAN ID</code> 相符，則在 <code>VLAN Receive=any</code> 時，交換器會移除 VLAN 標籤並轉送封包。<br/><code>optional</code> - 停用 VLAN 過濾。將帶有 VLAN 標籤 ID 但不存在於 VLAN 表中的封包，視為沒有 VLAN 標籤的封包處理。<br/><code>strict</code> - 啟用 VLAN 過濾並進行額外的 ingress 過濾，檢查 ingress 埠是否為 VLAN 表中所接收 VLAN ID 的成員。ingress 埠上接收到的 VLAN ID 與 VLAN 表不相符的封包將被捨棄。access 埠必須指定 Default VLAN ID，因為它會用於標記該埠的 ingress 流量，並移除 egress 流量的標籤。 |
| **VLAN Receive** (*any \| only tagged \| only untagged*; Default: **optional**) | 根據 VLAN 標籤是否存在來過濾接收的流量。<br/><code>any</code> - 允許特定埠上有帶標籤與未帶標籤的封包<br/><code>only tagged</code> - 只允許帶有 VLAN 標籤的封包。"Default VLAN ID" 將無法運作，因為它僅適用於未帶標籤的流量<br/><code>only untagged</code> - 只允許沒有 VLAN 標籤的封包 |
| **Default VLAN ID** (*integer: 1..4095*; Default: **1**) | 交換器會將接收到的未帶標籤封包放入 "Default VLAN ID" VLAN。僅對未帶標籤流量生效，且必須在 **VLAN Receive** 設為 "any" 或 "only untagged" 時才有效。不適用於帶標籤流量。此參數通常用於將 access 埠指派至特定 VLAN。當封包的 VLAN ID 與 Default VLAN ID 相符時，也用於移除 egress 流量的標籤。 |
| **Force VLAN ID** (*yes \| no*; Default: **no**) | 將 `Default VLAN ID` 值指派給所有 ingress 流量（帶標籤與未帶標籤）。在所有 VLAN Mode 中都會生效。如果埠接收到帶標籤流量，且 `Default VLAN ID` 設為 1，則啟用此參數後，egress 流量將不帶標籤。 |

交換器埠的 VLAN 成員設定。

![Swos vlans css610](/img/bdb180a9a3afc27b.webp)

| Property | Description |
| --- | --- |
| **VLAN ID** (*integer: 1..4095*; Default: **0**) | 要指派埠的 VLAN ID |
| **IGMP Snooping** (*yes \| no*; Default: **no**) | 在指定的 VLAN 上啟用或停用 IGMP Snooping。啟用時，交換器會監聽來自指定 VLAN 的 IGMP Join 與 Leave 要求，並且只將流量轉送至已從指定 VLAN 傳送 IGMP 成員要求的埠。停用時，交換器會將 Multicast 流量泛送至所有 VLAN 成員埠。 |
| **Members** (*ports*; Default: **none**) | 允許在指定 VLAN 上轉送流量的埠群組 |

### VLAN 設定範例 {#vlan-configuration-examples}

#### Trunk 與 Access 埠 {#trunk-and-access-ports}

![Access ports](/img/dcbdce357964f958.webp)

1. 在 VLANs 選單中新增 VLAN 項目，並指定埠成員。

![Css610 vlans](/img/dd2937f9ae0a3398.webp)

1. 在 VLAN 選單中，於預計作為 access 的埠上設定 Default VLAN ID（未帶標籤），選擇正確的 VLAN Receive 設定（Port2 為 only tagged，Port6-8 為 only untagged），並啟用 strict VLAN 過濾，以確保只有允許的 VLAN 可以通過這些埠。

![Css610 vlan](/img/8fb78913b7a9e9ab.webp)

#### Trunk 與 Hybrid 埠 {#trunk-and-hybrid-ports}

![Hybrid ports](/img/90b987271e134d95.webp)

1. 在 VLANs 選單中新增 VLAN 項目，並指定埠成員資格。

![Css610 vlans hybrid](/img/167fe7083c6b6f90.webp)

1. 在 VLAN 選單中，於預計作為 hybrid 的埠上設定 Default VLAN ID（用於 untagged VLAN），選擇正確的 VLAN Receive 設定（Port2 僅限 tagged，Port6-8 為 any），並啟用 strict VLAN filtering，以確保只有允許的 VLAN 能通過這些埠。

![Css610 vlan hybrid](/img/2d8b9483f5a9f2de.webp)

#### 管理存取 {#management-access}

在此範例中，將在 VLAN 200 上建立交換器管理存取。設定架構與「**Trunk 與 Access 埠**」相同，且步驟 **1.、2.** 一致。額外的 **第 3** 步驟需要在 System 選單中指定管理 VLAN ID。套用設定後，交換器只會回應 Port2 上 tagged VLAN 200 的封包，以及 Port6 上的 untagged 封包。DHCP 用戶端也會在指定的 VLAN ID 中運作。

![Css610 system vlan](/img/2a14134bc28aaf54.webp)

> **警告：** 如果 VLAN 設定不正確，變更管理 VLAN 可能會完全停用對交換器管理的存取。變更此設定前請儲存設定備份，若管理存取遺失，請使用 [Reset and Reinstall](#reset-and-reinstall)。

## Hosts

此表格代表動態學習到的 MAC 位址與埠對應項目。它可能包含兩種類型的項目：動態與靜態。動態項目會自動新增，這也稱為學習程序：當交換器從某個埠收到封包時，它會將封包的來源 MAC 位址與收到封包的埠新增到 host table，因此當具有特定目的 MAC 位址的封包進入時，它就知道應將封包轉送至哪個埠。如果目的 MAC 位址不存在於 host table 中，則會將封包轉送至群組中的所有埠。動態項目約 5 分鐘後逾時。

如果已存在具有相同 MAC 位址的動態項目，靜態項目將會取代動態項目。新增靜態項目也可使用更多功能。

![Swos shost css610](/img/d22df8b89cf64db5.webp)

**靜態主機屬性**

| 屬性 | 說明 |
| --- | --- |
| **Ports** | 封包應轉送至的埠 |
| **MAC** | MAC 位址 |

**動態主機屬性（唯讀）**

| 屬性 | 說明 |
| --- | --- |
| **Port** | 封包應轉送至的埠 |
| **MAC** | 已學習到的 MAC 位址 |

## SNMP

SwOS 支援 SNMP v1 與 v2c（回應 GetRequest、GetNextRequest 與 GetBulkRequest），並使用 IF-MIB、SNMPv2-MIB、BRIDGE-MIB 與 MIKROTIK-MIB（僅用於健康狀態、PoE-out 與 SFP 診斷）。不支援 SNMP traps 與寫入 SwOS 設定。

## ACL 與 ACL Stats 標籤頁 {#acl-and-acl-stats-tabs}

存取控制清單（ACL）規則表是非常強大的工具，可根據 L2、L3 與 L4 通訊協定標頭欄位條件，進行線速封包過濾、轉送與 VLAN 標記。每條規則都包含條件部分與動作部分。

![CSS610 ACL table](/img/38f5c04e1dfbc157.webp)

**條件部分參數**

| 屬性 | 描述 |
| --- | --- |
| **From** | 封包進入的埠 |
| **MAC Src** | 來源 MAC 位址與遮罩 |
| **MAC Dst** | 目的 MAC 位址與遮罩 |
| **Ethertype** | 封裝在 Ethernet Frame 酬載中的協定 |
| **VLAN** | VLAN 標頭是否存在：`any` / `present` / `not present` |
| **VLAN ID** | VLAN 標籤 ID |
| **Priority** | VLAN 標籤中的優先順序 |
| **IP Src** (IP/netmask:port) | 來源 IPv4 位址、網路遮罩與 L4 埠號 |
| **IP Dst** (IP/netmask:port) | 目的 IPv4 位址、網路遮罩與 L4 埠號 |
| **Protocol** *(integer)* | IP 協定 |
| **DSCP** | IP DSCP 欄位 |

**動作部分參數**

| 屬性 | 描述 |
| --- | --- |
| **Account as** | 選擇要比對封包計入的計數器 |
| **Redirect To** | 強制新封包的目的埠 |
| **Mirror** | 複製封包並傳送至 mirror-target 埠 |
| **Drop** | 捨棄封包 |
| **Set VLAN ID** | 若存在 VLAN 標籤，則變更 VLAN 標籤 ID |

| **DSCP** | 變更 IP DSCP 欄位 |

每條 ACL 規則都可以指派至特定計數器，比對到的封包將計入該計數器。

## 重設與重新安裝 {#reset-and-reinstall}

CSS610 內建備份 SwOS 韌體，當標準韌體損毀或升級失敗時可以載入：

- 在設備開機時按住 Reset 按鈕幾秒，將重設設定並載入備份韌體。
- 載入備份韌體後，可以使用網頁瀏覽器連線至 192.168.88.1（或由 DHCP 伺服器提供的租用位址），並安裝新的 SwOS 韌體。
