TR069-client 實現 CPE WAN 管理協定（CWMP）以進行遠端裝置管理，該協定由寬頻論壇（BBF）標準化。CWMP 透過 IP 網路使用 HTTP(S) 與自動配置伺服器（ACS）通訊，ACS 可以監控、配置屬性並更新遠端裝置的韌體。它通常由 ISP 用於管理 CPE，但也可用於網路基礎設施裝置管理。

需要 tr069-client 軟體包。

### 配置設定 {#configuration-settings}

**子選單：** `/tr069-client`

TR069-client 選單引數：

##### 可寫設定 {#writable-settings}

用戶端配置設定。

| 屬性 | 描述 |
| :-- | :-- |
| **enabled** | 啟用/停用 CWMP 協定 |
| **acs-url** | ACS 的 URL。示例："[https://example.com:8080/path/](../getting-started/configuration-management/list-of-menus-with-sensitive-parameters.md)"、"[https://192.168.1.100/](https://192.168.1.100/)"  如果使用 HTTPS 訪問 ACS，則必須在用戶端的[證書儲存](../authentication-authorization-accounting/certificates.md)中匯入 Root CA，以驗證 ACS 伺服器證書。 |
| **username** | HTTP 認證使用者名稱（由 CPE 用於“登入”到 ACS） |
| **password** *[敏感](../getting-started/configuration-management/list-of-menus-with-sensitive-parameters.md)* | HTTP 認證密碼（由 CPE 用於“登入”到 ACS） |
| **periodic-inform-enabled** | 啟用/停用 CPE 週期性會話發起。定時器在每個成功會話後啟動。當會話由週期性間隔啟動時，Inform RPC 會包含 "2 PERIODIC" 事件。對映到 "Device.ManagementServer.PeriodicInformEnable" 引數 |
| **periodic-inform-interval** | 週期性 Inform 的定時器間隔。對映到 "Device.ManagementServer.PeriodicInformInterval" |
| **client-certificate** | 用戶端/CPE 的證書，ACS 可將其用於額外認證 |

##### 只讀設定 {#read-only-settings}

用於監控用戶端狀態的只讀引數。

| 屬性 | 描述 |
| :-- | :-- |
| **status** | CWMP 的資訊狀態。disabled - 協定已停用，waiting-URL - 協定已啟用，但未配置 ACS URL，running - CWMP 配置正確，並會在事件發生時與 ACS 通訊 |
| **last-session-error** | 使用者友好的錯誤描述，說明上一次會話為何未能成功完成 |
| **retry-count** | 連續未成功會話計數。如果 > 0，則 last-session-error 應指示錯誤。成功會話、停用協定或重啟後重設為 0 |

##### 命令 {#commands}

| 命令 | 描述 |
| :-- | :-- |
| **reset-tr069-config** | 完全重設並忘記 tr069-client 配置和狀態（不影響其他 ROS 配置）。當 CWMP 進入無響應/掛起狀態，並且需要在不重新安裝 RouterOS 的情況下恢復時使用。 |

### CWMP 會話 {#cwmp-session}

CWMP 用戶端通常會在不同事件（首次啟動、重啟、週期性間隔、遠端請求、值變更等）發生時啟動與 ACS 的通訊（會話）。在每個會話中，CPE 和 ACS 可以呼叫 RPC 以在對方“執行”。CPE 始終以 Inform RPC 開始，其中包含連線原因、裝置資訊以及一些取決於配置的 Parameter 值。當 CPE 沒有更多內容要說時，ACS 會執行其 RPC（大多數情況下是 Parameter 管理 RPC）。

### 引數和資料模型 {#parameters-and-data-models}

引數是簡單的名稱+值對，每個廠商可以決定其裝置支援哪些引數。所有受支援引數的組合稱為資料模型（DM）。BBF 定義了三個根資料模型（TR-098、TR-181:1、TR-181:2），廠商應基於這些模型提供其支援的引數。**RouterOS 資料模型基於 "TR-181 Issue 2 Amendment 11"**，這是最新的 DM，並由 BBF 推薦。

RouterOS TR069 用戶端支援的[引數參考](pathname:///assets/tr069_parameters.html)

### 下載 RPC {#download-rpc}

#### RouterOS 更新（1 Firmware Upgrade Image） {#routeros-update-1-firmware-upgrade-image}

CWMP 標準規定，可以使用 Download RPC 並透過 FileType="1 Firmware Upgrade Image" 以及一個可下載檔案的單個 URL（支援 HTTP 和 HTTPS）來更新 CPE 的韌體。該標準還指出，下載的檔案可以是任意型別，並且可以應用廠商特定的流程來完成韌體更新。由於 MikroTik 的更新基於軟體包（同時也是為了額外的靈活性），因此使用 XML 檔案來描述韌體升級/降級。目前，XML 配置支援提供多個檔案 URL，這些檔案將被下載，並像透過韌體/軟體包檔案上傳進行常規 RouterOS 更新一樣應用。

以下是 RouterOS 捆綁軟體包和 tr069-client 軟體包更新的示例（不要忘記也更新 tr069-client 軟體包）。應將 XML 檔案放在某個 HTTP 伺服器上，CPE 可訪問該伺服器進行下載。此外，可下載的 RouterOS 軟體包檔案也應以相同方式可訪問（可以位於任意 HTTP 伺服器上）。使用 ACS，執行 Download RPC，其 URL 指向 XML 檔案（例如 "https://example.com/path/upgrade.xml"），內容如下：

```
<upgrade version="1" type="links">
   <config/>
   <links>
       <link>
          <url>https://example.com/routeros-mipsbe-X.Y.Z.npk</url>
       </link>
       <link>
          <url>https://example.com/tr069-client-X.Y.Z-mipsbe.npk</url>
       </link>
   </links>
</upgrade>

```

CPE 將下載 XML，解析/驗證其內容，從提供的 URL 下載檔案並嘗試升級。結果將透過 TransferComplete RPC 報告。

:::info
注意

始終以增量方式進行韌體更新 - 首先，更新一臺經過本地測試的裝置，並確保 CWMP 通訊在更新到新版本後恢復，且所需的 ROS 功能正常工作。其次，透過增量更新 CPE 分組來重複這些步驟。我們不建議一次性更新所有遠端裝置。

**警告：** 在生產環境中使用 HTTPS 進行韌體管理
:::

#### 配置更改（3 Vendor Configuration File） {#configuration-change-3-vendor-configuration-file}

同一個 Download RPC 可用於執行完整配置覆蓋（按標準意圖）或配置修改（當 URL 的檔名副檔名為 ".alter" 時）。

#### 修改配置 {#alter-configuration}

RouterOS 有許多配置屬性，並非所有內容都能移植到 CWMP 引數。這就是 RouterOS 提供執行其強大指令碼語言來配置任意屬性的可能性的原因。可以使用 Download RPC FileType="3 Vendor Configuration File" 並搭配副檔名為 ".alter" 的可下載檔案來執行配置修改（這實際上就是常規指令碼執行）。藉助此強大功能，可以配置透過 CWMP 引數無法使用的任意 ROS 屬性。

#### 覆蓋所有配置 {#overwrite-all-configurations}

可以使用 Download RPC FileType="3 Vendor Configuration File" 並搭配任意 URL 檔名（".alter" 副檔名除外）來執行完整的 ROS 配置覆蓋。

**警告：** 提供的配置檔案（指令碼）必須足夠“智慧”，以便在重啟後立即正確應用配置。當使用透過 Upload RPC 上傳的配置檔案時，這一點尤其重要，因為它只包含匯出的值。以下是一些應手動新增的內容：

- 介面顯示出來的[啟動延遲](../getting-started/configuration-management/index.md#startup-delay)。
- 使用者的隱藏密碼。
- [證書](../authentication-authorization-accounting/certificates.md)。

#### RouterOS 預設配置更改（X MIKROTIK Factory Configuration File） {#routeros-default-configuration-change-x-mikrotik-factory-configuration-file}

此廠商特定的 FileType 允許更改在執行 `/system/reset-configuration` 命令時（或透過其他方式重設路由器配置時）執行的 RouterOS 預設配置指令碼。

:::warning
注意

如果預設配置指令碼被更改，則 `/system/default-configuration/print` 不會顯示它，就像透過 Netinstall 工具更改該指令碼時的情況一樣。該命令將始終顯示由 MikroTik 設定的預設指令碼。

**警告：** 請謹慎使用，因為上傳的指令碼失敗可能會導致裝置無法操作和/或 ACS 無法訪問
:::

### FactoryReset RPC {#factoryreset-rpc}

這是一個 CWMP 標準 RPC，用於執行 RouterOS 配置出廠重設。重設過程的執行方式與執行以下命令相同：

```
/system/reset-configuration skip-backup=yes

```

請注意，出廠預設配置可能因裝置而異（參見[預設配置](../getting-started/configuration-management/default-configurations.md)），並且執行此命令會移除所有配置並執行內部儲存的 default-configuration 指令碼。

### 上傳 RPC {#upload-rpc}

##### 上傳當前配置（1 Vendor Configuration File） {#upload-current-configuration-1-vendor-configuration-file}

其結果是上傳到 ACS 的檔案，與 RouterOS 中 `/export` 命令的輸出相同

##### 上傳日誌檔案（2 Vendor Log File） {#upload-log-file-2-vendor-log-file}

其結果是上傳到 ACS 的檔案，與 RouterOS 中 `/log/print` 命令的輸出類似

##### 上傳預設配置（X MIKROTIK Factory Configuration File） {#upload-default-configuration-x-mikrotik-factory-configuration-file}

其結果是上傳到 ACS 的檔案，其內容為當前設定的預設配置指令碼；如果執行 `/system/reset-configuration` 命令，就會執行該指令碼。它可能與使用 `/system/default-configuration/print` 返回的內容不同。

### 安全 {#security}

- HTTP 只應在安全/專用網路中測試初始設定時使用，因為中間人攻擊者可以讀取/更改配置引數。**在生產環境中，HTTPS 是必須的**。
- CWMP 的入站連線驗證在設計上是安全的，因為 CPE 不會與除先前配置的 ACS 之外的任何其他裝置通訊。Connection Request 只會通知 CPE 與先前配置的 ACS 啟動新連線 + 新會話。

### 讓路由器準備好用於 TR069 {#get-the-router-ready-for-use-with-tr069}

本最佳實踐指南展示了一個 RouterOS 初始設定示例，適用於需要使用自定義配置進行安全/預配置的出廠重設的情況，尤其是在使用 TR-069 時。當用戶（或提供商在不知情的情況下）將裝置誤配置到不可逆轉的狀態時，這會很有用。然後可以使用 TR069 FactoryReset RPC、透過 RouterOS `/system/reset-configuration`，或使用路由器上的重設按鈕來應用出廠重設配置。

##### 在 Netinstall 上覆蓋出廠預設配置 {#overriding-factory-default-configurations-on-netinstall}

執行 Netinstall 時，可以調整 default-configuration 指令碼以滿足特定需求，並透過覆蓋 MikroTik 的預設指令碼來安裝它。希望將 FactoryReset 作為備份的提供商會這樣做，以便在某些無法解決的錯誤配置情況下使裝置再次“可達”。在 TR-069 情況下，default-configuration 指令碼至少應匯入證書、設定 IP 層連通性、啟用並配置 tr069-client、配置防火牆。之後，其他配置可以由 ACS 執行。

:::warning
在出廠重設時，所有證書也會被移除，因此如果重設後需要這些證書，則 default-configuration 指令碼必須匯入它們
:::
