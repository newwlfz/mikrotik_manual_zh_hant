## 概述 {#overview}

佇列型別類似於無類排隊規則的模板——這些演算法控制封包在進一步傳輸前如何被丟棄或排隊到記憶體緩衝區中。它們對於確保良好的服務質量至關重要，因為當超出頻寬限制時，它們不僅能提供幫助，還會影響延遲等其他方面。

它們的複雜度和屬性差異很大。例如，先進先出（FIFO）佇列很簡單，並能確保封包處理順序的公平性，但它可能導致隊頭阻塞等問題。更復雜的佇列型別（例如實現公平排隊或擁塞避免的型別）可以更有效地幫助管理網路效能，但它們可能需要更多資源和配置。

因此，佇列型別的選擇取決於網路的具體需求和特徵。

## 佇列型別一覽 {#queue-types-at-a-glance}

1. **BFIFO（位元組先進先出）：**

    - **特性：** BFIFO 是一種簡單的面向位元組的排隊規則，它會按照封包到達的順序並基於其大小來發送封包。
    - **優點：** 封包管理簡單且公平。
    - **缺點：** BFIFO 可能導致隊頭阻塞，即一個大的封包會延遲其後面所有較小的封包。此外，它沒有防止擁塞或對封包劃分優先順序的機制。
2. **PFIFO（封包先進先出）：**

    - **特性：** 類似 BFIFO，但以封包為單位而不是位元組。
    - **優點：** 易於實現和理解。就封包數量而言是公平的。
    - **缺點：** 與 BFIFO 一樣，它會受到隊頭阻塞的影響，並且沒有任何擁塞管理機制。
3. **CAKE（通用應用增強）：**

   - **特性：** 一個全面的佇列管理系統，旨在對抗緩衝膨脹並確保公平排隊。它結合了 CoDel、FQ 和其他技術。
   - **優點：** 在任何網路條件下都能出色地管理延遲。它特別適用於消費級寬頻連線。
   - **缺點：** 配置比更簡單的排隊規則更復雜。並非適用於所有用例，尤其是在需要精細控制的情況下。
4. **CoDel（受控延遲）：**

   - **特性：** CoDel 旨在透過丟棄封包來控制佇列延遲，從而改善緩衝膨脹。
   - **優點：** 擅長管理延遲並避免緩衝膨脹。
   - **缺點：** CoDel 本身不提供公平排隊。
5. **FQ\_CoDel（公平排隊受控延遲）：**

   - **特性：** 將 CoDel 的延遲管理與公平排隊相結合。
   - **優點：** 出色的延遲管理以及在流之間公平分配頻寬。通常被認為是良好的預設選擇。
   - **缺點：** 比更簡單的佇列規則更復雜，這可能使其更難配置。
6. **MQ\_PFIFO（多佇列封包先進先出）：**

   - **特性：** MQ\_PFIFO 是 PFIFO 的擴充套件，支援多個佇列。
   - **優點：** 允許為不同型別或優先順序的流量使用不同的佇列。
   - **缺點：** 仍然受到隊頭阻塞的影響，並且缺少內建的擁塞管理機制。
7. **RED（隨機早期檢測）：**

   - **特性：** RED 旨在透過在佇列變滿之前隨機丟棄封包來預測並防止擁塞。
   - **優點：** 有助於防止擁塞，並能提高整體網路效能。
   - **缺點：** 配置可能很複雜，並且需要根據網路的具體特徵進行調整。配置錯誤可能導致效能下降。
8. **SFQ（隨機公平排隊）：**

   - **特性：** SFQ 旨在透過將流分配到不同的動態佇列來確保流之間資源的公平分配。
   - **優點：** 有助於防止單個流獨佔連線。
   - **缺點：** SFQ 不管理延遲或擁塞。佇列數量還可能增加記憶體使用量。

在選擇佇列規則時，你需要考慮網路的特徵以及你最優先考慮的因素，例如延遲、公平性、簡單性或擁塞管理。
